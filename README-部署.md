# 撸货记账 · 部署与使用

一个单页应用（PWA），手机 iPhone / 安卓、电脑浏览器都能用，两端记同一本账实时同步。
同步协议与「五行理财」（www0706.netlify.app）完全同源：复用其 Cloudflare Worker 存储，
按独立身份隔离，撸货账本和理财数据互不可见。

## 首次使用（每台设备）

1. 打开上面的网址
2. iPhone：Safari 分享 → **添加到主屏幕**，之后从桌面图标进，就是全屏 App
3. 手机和电脑各生成自己的同步码（设置页可见），把一端的码粘到另一端 → 两端共用同一本账

## 两台设备怎么共用一本账

- 设备 A：右上角 设置 → 我的同步码 → 复制
- 设备 B：设置 → 导入另一台的同步码 → 粘贴 → 导入并配对
- 之后任何一端改动都会自动推到云端，另一端下次打开自动拉取（改动期间也在页面上则会即时同步）
- 换新手机 / 清了浏览器数据：用同步码重新配对一次，账本从云端回来

## 日常记法（v21 简化版）

- 状态只有两个：**在途**（垫了钱还没结清）/ **已回款**。不再区分发货、寄出这些过程。
  - **v21 起「自留」已移除**：货自己留着用就不算生意，直接**把那一单删掉**即可（删除＝这单的钱不再出现在任何汇总里，这是这一取舍的代价，想留痕就给它记个备注）。
  - **旧账本里的「自留」单不会被改写**：升级后它们仍是「自留」，显示成「**自留（旧）**」，金额口径不变（利润＝回款−垫付−邮费，仍计入已结算净盈亏，也不算在途）。它们只能出现在「**全部**」筛选里，用户自己决定删还是留——程序不会替你动这笔账。
- 右下角「＋记一单」：必填只有**商品名称 + 垫付金额**，日期默认今天、其余全是一键可选，改完即存。
- 邮费：每单的运费/邮费记在「邮费」栏（垫付金额旁边），利润＝回款 − 垫付 − 邮费，不填按 0 算。
  一次采购多个型号、整批一起寄时不必逐单猜邮费，用下面的「批量结算」统一分摊。
- 收到钱：点「回款」，金额默认垫付价，有 **+10/+20/+50/+100** 快捷加价和利润实时预览，确认即入账。
- 批量结算（v17 新增，v19 起成批留痕）：整批一起寄、对方回一笔总款时，点账本筛选行右侧的「**批量结算**」：
  勾选本次一起寄出的在途单（默认全选），填**本批邮费（整批合计）**和**对方总回款**，
  系统按各单垫付占比自动分摊到每单，并把勾选的单子置为「已回款」。
  回款还没到就把总回款**留空**，先只分摊邮费、单子保持「在途」，等对方回款了再对这批单跑一次批量结算补回款。
- 批次（v19）：结算过的这一批会从此绑在一起——
  - **账本页**：同批的单子收在一条「一起寄出 · 日期」表头下面，表头写整批口径（N 单 / 垫付合计 /
      邮费合计 / 回款合计），单张卡片左侧一道青瓷竖条；卡片里也直接看得到这一单摊到的邮费。
  - **再次批量结算**：弹窗里这批的单子归在一个「一起寄 · 日期」分组下，点分组那一行的勾选框
     就能**整批勾选/取消**，不用凭记忆一单单挑；分组上还会写「已分摊邮费 ¥45」，一眼看出这批的
      邮费已经摊过、这次只补回款就行（邮费栏留空）。同一批原班人马再结一次 → 续用原批次；
      只勾一半或混着别的单 → 另起一批。
  - **报表页「邮费统计」**：本期邮费合计，下面按批一行行列出「一起寄 · 日期 · N 单 · 邮费 · 回款」
      以及这一批都是哪些货（商品名），单寄没成批的合并成「单寄（未成批）」一行。
      一行里的金额是**成员明细合计**（这一批各单自己记的邮费/回款加起来）——也就是真实花掉/收回的钱；
      与录入那一批时的整批数字不同时，行里会补一句「整批录入 邮费 ¥X」（只说明，不改数）。
  - **退出本批（v20）**：结错批了，就在那张单的卡片上点「**退出本批**」，它从此不再和这一批绑在一起。
      整批已经分摊到它头上的邮费/回款**留在它自己身上**照旧算利润（只解绑、不改钱）；如果退出后这一批
      只剩 1 单，那 1 单也一并退出批次（不留「一个人」的批次）。只剩 1 单的批次不再显示「一起寄出」表头。
  - **口径怎么看（v21 定稿）**：**统计只认单子上真实记的邮费/回款**，批次只决定分组与归期：
      - 批次表头一行写的是**整批**口径（标着「整批：」）——那是当初结算时你**录入**的整批数字，留作对账，
        它**不参与任何统计**；
      - 成员卡片上写的是**这一单自己**的明细，报表/看板的邮费都按各单明细汇总：
        「本期邮费合计 ＝ 各批成员邮费之和 ＋ 单寄邮费之和」，恒等于这一期所有单子上记的邮费总和。
        （v20 之前是按整批录入值算的，于是①有人「退出本批」时那单的分摊额会被重复计一次、
        ②成员入批前自己已记过邮费时会少算——v21 全部改成明细口径后这两个毛病一起消失。）
      - 筛选把一批切开时，表头会补一行「本页只显示其中 N 单，另有 M 单被筛选隐藏」；
      - **有人点过「退出本批」**：表头写「**已有 N 单退出本批，整批口径仍含它们**」（陈述，不是告警）；
      - 成员数没变却合不上（手工改过某单邮费、或成员入批前自带邮费）：表头才标
        「**≠ 成员明细合计 …，与整批口径不同**」（红棕告警色，只提示不改钱）。
      - 结算时会把**当时的成员数**（batchCount）冗余记在每张单上，专门用来区分上面这两种情况；
        退出的人把 batchCount 留给了还在批里的单，剩下的人原班人马再结一次时它会被重写成新人数。
- 同款好货：点「再来一单」打开记单表单并**预填原单**（商品/数量/垫付/邮费/渠道/备注/平台），
  日期自动今天、状态在途、回款清空，改一改保存即新建。
- 没出掉：v21 起**直接删掉那一单**（「自留」状态已移除）；老账本里已有的「自留（旧）」单子想删也是点「删除」。
- 0 元购/白嫖单：垫付金额直接填 0，保存时确认一下即可（v9 起支持）。
- 主题：v14 起定稿「青瓷薄荷」浅色玻璃风（绿松石 #14b8a6/#2dd4bf，固定浅色，手机开深色模式也用浅色）。
- 报表页：**月 / 季 / 年** 切换 + ‹ › 翻期，自动生成总结（单数、垫出、收回、净盈亏、环比上期），
  季报/年报带分月盈亏柱状图，另有已结算利润 Top5 商品榜。
- 看板页重点盯「垫付在外未回笼」大字卡（垫出去还没回来的钱）；「本月垫出」格下另有一行本月邮费。

  删单不留孤儿）；账本页同批单子按「一起寄出」分组显示、批次表头走整批口径、卡片直接显示本单摊到的邮费
  （金额栏改成两列，垫付/回款 + 邮费/利润）；批量结算弹窗按批次分组、分组勾选框一整批一键勾选、
  显示「已分摊邮费 ¥X」，整批原班人马再结一次续用原批次（只勾一半则另起一批）；
  报表页新增「邮费统计」卡（本期邮费合计 + 按批明细含商品名 + 单寄汇总），报表总结句也带上本期邮费
- v20（2026-09-20）：批次功能的**边界加固**，不新增流程——
  ①「退出本批」：批内单卡片上新按钮，结错批可把某单摘出（只解绑，已分摊到它的邮费/回款留在它身上；
  退出后该批只剩 1 单时，那 1 单也一并退出）；
  ②表头口径写明「整批：」，筛选把一批切开时补一行「本页只显示其中 N 单，另有 M 单被筛选隐藏」；
  ③手工改过批内单邮费、或单给某单回款后，表头标「≠ 成员明细合计 …，与整批口径不同」（只提示不改钱）；
  ④删批内单的确认框带上批次信息（属于一起寄出的 N 单之一 / 删完还剩几单）；
  ⑤只剩 1 单的批次不再显示「一起寄出」表头；同批单子聚成一块，散单不再被夹在批次表头和成员之间；
  ⑥顺手修两个老 bug：订单状态「自留」刷新/云同步后被错误打回「在途」（v4 起就存在）、
  筛选选「全部」刷新后被重置成「在途」；
  ⑦看板「本月垫出」格下补一行「另有邮费 ¥X」（归期同报表页：整批按批次日期、单寄按下单日期）
- v21（2026-09-20）：**统计口径修正 + 状态模型收敛 + 手机排版**
  ①**邮费统计口径改为「成员明细合计」**（真实缺陷修复）：报表页「本期邮费合计」与看板「另有邮费」
  一律按**各单自己记的 fee** 汇总，批次只决定分组与归期、不再作为统计取值。
  改前（v20）：成批的按 `max(batchFee)` 算 + 单寄按 fee 算——于是「退出本批」后，退出那单的分摊额
  既留在剩余成员的整批口径里、又作为单寄单被计一次，**邮费被重复计**（3 单摊 ¥21 + 散单 ¥6 应为 ¥27，
  退出 1 单后显示 ¥34）；反过来，成员入批前自己记过邮费时（submitBatch 对邮费是有意累加）又会**少算**。
  改后恒有：`本期邮费合计 = Σ各批成员 fee + Σ单寄 fee = 本期归期所有单子的 fee 之和`。
  批次表头仍显示**你录入**的整批数字（有对账价值）；报表批次行在同一口径下补「整批录入 邮费 ¥X」备注。
  ②**「退出本批」不再误报口径漂移**：结算时把当时的成员数冗余记成 `batchCount`（老数据缺失＝0），
  表头据它分两种措辞——有人退出 →「已有 N 单退出本批，整批口径仍含它们」（陈述）；
  成员数没变却合不上 → 仍是「≠ 成员明细合计 …，与整批口径不同」（告警，换成红棕色，v20 用的灰蓝
  和普通提示几乎同色肉眼分不出）。
  ③**移除「自留」状态**（用户决定）：状态只有在途/已回款，记单/编辑的下拉、账本筛选（三个 chip：
  在途/全部/已回款）都不再提供自留。**旧数据绝不静默改写**：已有的「自留」（含更老的「翻车自留」）
  原样保留，显示成「自留（旧）」，金额口径不变（仍计入已结算净盈亏、不算在途），只能在「全部」里
  看到并自行删除；看板环形图与状态行按「现役两态 + 数据里真有的遗留态」渲染，各块垫付之和恒等于
  「垫付合计」（占比不会因自留不在状态表里就少一块）。代价：用户删掉自留单后，那笔钱不再出现在
  任何汇总里——这是用户接受的取舍。
  ④手机筛选行排版：chip 内边距 6px 14px→6px 10px、gap 8px→6px，并加 `flex-wrap` 兜底
  （去掉原来的横向滚动裁切），390/360/430px 三档下三个 chip 与「批量结算」都完整落在一行、无横向溢出。
  ⑤单成员批次的卡片上补一句「单独一批寄出」（它不显示批次表头，光有「退出本批」按钮看不出上下文）。
